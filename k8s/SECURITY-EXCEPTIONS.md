# Kubernetes security exceptions

These exceptions are narrow infrastructure requirements, not application defaults.

- `multus-daemonset.yaml`: only KSV-0009/0010/0017/0118/0121 are excepted. The digest-pinned thick node CNI requires host networking and host PID visibility so delegated plugins can enter the target pod network namespace, plus root/privileged execution and enumerated host CNI/kubelet paths. Both root filesystems are read-only, resource limits are set, and NAD RBAC is read-only. Revisit by 2027-07-16.
- `gtp5g-installer.yaml`: only KSV-0010/0014/0017/0121 are excepted. Host PID, privileged execution, writable package layer and the host-root mount are limited to compiling/loading commit `952fb419130f5fc44cac1874e8183312006b746c` on `plane=user-plane` tainted nodes. Host networking was removed and resources are bounded. Revisit by 2027-07-16.
- `ueransim-eks-values.yaml` and the repository-owned UE manifests: no privileged exception remains. The resident UE runs as UID 0 because it must create `/dev/net/tun`, but retains a read-only root filesystem, privilege escalation disabled, all other capabilities dropped, and only `NET_ADMIN`/`MKNOD`; writable `/tmp` and `/dev/net` are size-limited `emptyDir` mounts.
- `free5gc-eks-values.yaml` and the four dedicated `slice-data-plane/upf-*-values.yaml` files: no privileged UPF exception remains. gtp5g is installed by its node-scoped DaemonSet; the UPFs run as UID 0 because the runtime must create the gtp5g link and nftables NAT rules, but retain a read-only root filesystem, privilege escalation disabled, all capabilities dropped, and only `NET_ADMIN` added. `/tmp` is a size-limited `emptyDir`. The dedicated UPFs retain KubeLinter's narrowly documented `run-as-non-root` and `unsafe-sysctls` exceptions. Revisit by 2027-07-16 and confirm the profile with live PFCP/GTP traffic before release.
- `pfcp-evidence-collector.yaml`: host PID visibility, root, `SYS_ADMIN`/`SYS_PTRACE`/`NET_ADMIN`, and a read-only host mount of the exact `gtp5g-tunnel` binary are required to enter the selected UPF network namespace and issue read-only generic-netlink queries for kernel PDR/FAR/QER state that free5GC does not export. The CronJob is pinned to the tainted `plane=user-plane` node, maps a closed DNN-to-`nf` selector to the exact containerd cgroup, accepts no request input, has a read-only root filesystem, and its dedicated namespace Role is read-only (no `pods/exec`). Revisit by 2027-07-16.
- `gtp5g-metrics-exporter.yaml`: host PID visibility, UID 0 and `SYS_PTRACE` are required to read each UPF process's namespace-specific `/proc/<pid>/net/dev` counters. It cannot mutate gtp5g or enter another namespace, has no service-account token or host mount, is pinned to the tainted user-plane node, drops every other capability, and retains a read-only root filesystem. Revisit by 2027-07-16.
- Public subnets remain only for the explicitly internet-facing teaching frontend. free5GC WebUI and NEF use internal legacy NLB overlays; EKS nodes, Multus reference networks and 5GC workloads use private subnets through NAT.

Run `scripts/validate-k8s-security.sh`. It scans ordinary manifests with all default KubeLinter checks, then scans the two infrastructure DaemonSets separately while excluding only their documented check IDs. Trivy exceptions use exact file paths and expiry dates. No wildcard or directory-wide scanner skip is permitted.

The private NEF/WebUI NLB overlays exclude only KubeLinter's `dangling-service` check when scanned alone because their selected Deployments are produced by the pinned external Helm chart. The gate separately renders those exact subcharts, asserts all selector labels, and runs Kubeconform and Trivy over the result.
